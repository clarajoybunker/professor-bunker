# Interaction design and HCI
When users may struggle to understand, navigate or operate a design.

## Concepts and application cues

- **Mental models:** Investigate expectations formed by experience; do not assume users share the designer’s model.
- **Affordances / signifiers:** Distinguish possible actions from cues that communicate those actions.
- **Feedback / feedforward:** Show what happened and help users anticipate outcomes before acting.
- **Gulf of execution / evaluation:** Examine difficulty expressing intent and interpreting the system’s response.
- **Information architecture / navigation:** Establish content groupings, destinations, tasks, overlays and predictable return paths.
- **Progressive disclosure:** Reveal complexity as needed while keeping essential information discoverable.
- **Cognitive load / recognition vs recall:** Reduce unnecessary memory and processing demands; distinguish task complexity from interface burden.
- **Direct manipulation:** Consider visible controls and immediate feedback instead of indirect commands or chat when they suit the task.
- **Error prevention / recovery:** Prevent costly mistakes; support cancellation, undo, clear messages and restoration.
- **Accessibility / inclusive design:** Evaluate keyboard access, focus, contrast, semantics, text scaling, assistive technologies and diverse circumstances.

## Fictional example
A fictional greenhouse control app uses a chat box for temperature changes. Compare direct controls with conversation for frequent precise adjustments.

## Limits and misuse
Patterns depend on audience and task. Never claim accessibility compliance solely from a screenshot; test interaction and assistive technology.

## Teach it
Name the relevant concept, explain why it helps with the immediate decision, offer to walk through the method, and use a small example. Ask what would count as useful completion. Do not assign a framework merely because it exists.
